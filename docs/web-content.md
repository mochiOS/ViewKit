# Webコンテンツの埋め込み — 未リリースAPI

## 実装範囲

`extensions/web`の`viewkit-web`は、Webセッション・ページ・表示を分離する
追加クレートです。ViewKit本体へWebKit依存を追加しません。AppCoreとTerraの
現在の実装も変更していません。

実装済みなのはAPIの状態管理、要求と完了の分離、寿命管理、通知配送、Viewの
委譲です。**ネイティブWebKitアダプターは未接続で、公開コンストラクターは
`WebError::Unavailable`を返します。Webサイトの表示成功を意味しません。**
テスト専用のドライバーは`cfg(test)`の内側にのみ存在します。

## 所有権

- `WebSession`: Cookie・キャッシュなどを共有するページ群。UIスレッド専用。
- `WebPage`: 文書、履歴、読み込み状態。セッションへの強参照を保持する。
- `WebView`: 通常のViewKit View。ページと一つの表示オブジェクトを保持する。
- `WebSubscription`: 通知購読。Dropで解除する。ページ側はコールバックへの
  弱参照だけを保持し、コールバックがページを捕捉しても所有権の循環を作らない。

`WebView`は初期化時に一度作成し、Viewツリーを組み直す際はCloneする。
Cloneは同じ表示を共有する。新しい`WebView::new`を同一ページに対して二重に
呼ぶと`AlreadyPresented`を返す。最後の表示参照を破棄した後は、同じページを
表示し直せる。表示の破棄だけでは、アプリが保持するページを破棄しない。

同じ表示のCloneを複数のウィンドウへ同時に配置することは未対応。同一ページの
複数表示オブジェクトの作成は禁止できるが、既存ViewKitにはViewのマウント先を
識別する汎用契約がないため、Cloneの複数ウィンドウ配置の検出はまだできない。
実アダプター接続前に、ウィンドウへの付け外しと表示サイズ・DPI・可視性の更新を
扱う汎用的なライフサイクルを整備する。paintからresizeを呼ぶ代替にはしない。

`WebPage::close`は冪等で、終了要求を一度だけ送る。以後の操作を拒否し、
保持された表示への入力・描画とアプリへの通知を停止する。終了待ちは行わない。
最後のページ参照のDropでも、未送信の終了要求を一度だけ送る。

## 要求と状態

```rust,no_run
use viewkit_web::{WebSession, WebSessionOptions, WebView};

// 現時点ではここでUnavailableになる。以下は接続後の利用契約。
let session = WebSession::new(WebSessionOptions::default())?;
let page = session.create_page()?;
let subscription = page.subscribe(|event| {
    // UIスレッド上。ここから新たな要求や購読解除を行える。
    println!("{event:?}");
})?;
let navigation = page.load_url("https://example.com")?;
let view = WebView::new(page.clone())?;
// session/page/subscription/viewはアプリの状態として保持する。
# Ok::<(), viewkit_web::WebError>(())
```

`load_url`は検索語を補完せず、絶対URLの解析だけを行う。許可するスキームや
ファイルへのアクセスは実エンジン・アプリのナビゲーションポリシー・OSの
Capabilityで判定する。URLを渡してもファイルやネットワークの権限は増えない。

要求を受理した時点では`Requested`になる。開始通知で`Loading`、メイン文書の
コミット後に完了通知を受けた場合だけ`Ready`になる。URLとタイトルは実エンジン
のコミット値を使用する。コミット前の完了通知では成功にしない。不正なコミット
URLは失敗とする。HTTPSという文字列だけからTLS検証済み表示を作らない。

要求IDはページ内で再利用しない。拒否された要求のIDも消費する。リダイレクトは
同じIDを使う。古い要求の完了・失敗・タイトル・履歴可否で、新しい要求の状態を
上書きしない。履歴の有無はエンジンの報告を使い、アプリのURL履歴から推測しない。
`stop`の受理だけでは`Stopped`にしない。プロセス終了は`Terminated`であり成功では
ない。自動復旧や自動再送は行わず、新しいページの作成を必要とする。

## 通知配送

既存の`UiSubscription`/`UiNotifier`でUIイベントループへ配送する。ワーカーは
通知キューへ追加するだけで、View・ページ状態・アプリのコールバックを操作しない。
ドライバーのdispatchはUIスレッドで、1回64件以内の作業に制限する。残りがあれば
次のターンを予約する。アプリ側にpollやタイマーを要求しない。

ページ状態はViewKitの`State`へ保存し、実際に変更された時だけ再構築を通知する。
同じターン内の状態変更通知はまとめる。コールバック中に読み込みや購読解除を
行っても内部のRefCellを借用したまま呼び出さない。配送中に別の購読を解除すると、
その購読には続きの通知を送らない。明示的にページを閉じると以後の通知を止める。

バックエンド通知キューは256件、文字列データは合計4 MiBまで。超過した場合は
通知を黙って落として成功を表示せず、セッションを停止し、ページを明確な失敗に
する。実C ABIアダプターでも、文字列を確保・コピーする前に長さを検証する必要が
ある。このメモリ制限は内部の防御であり、WebKitのサンドボックスの代わりではない。

## 表示と未接続部分

`WebView`は背景・ボーダー・ツールバーを追加せず、通常のViewへmeasure/paintと
イベントを委譲する。これらの呼び出しからエンジンのdispatchや読み込みを行わない。
テストでは描画中にdispatch/コマンド送信が発生しないことを確認している。

実アダプターに必要な次の接続は未実装:

- 完成フレームの保持・解放、物理ピクセルと論理サイズ、DPI、damageの統合。
- 汎用マウントライフサイクル、可視性、複数ウィンドウの同時使用の拒否。
- mochiOS IME、選択範囲、フォーカス、キーボード、クリップボード。
- WebアクセシビリティツリーとViewKit側の連携。
- AppCoreのファイル選択・保存・ダウンロード先への安全な接続。
- 新規ウィンドウ、認証、サイト権限、未処理要求の拒否・取消。
- カスタムスキーム、JavaScriptブリッジ、永続Webサイトデータ、Kome ABI。

保存方式は初版では`Ephemeral`だけを定義し、永続保存を受理したふりはしない。
ブラウザのタブ・URL欄・ブックマーク・履歴一覧・`terra:///`のルーティングはTerraが
所有し、AppCoreへブラウザ固有APIは追加しない。C ABIの現在の案に不足する操作や
通知があれば、未リリースの境界として見直す。API名だけを実装済み機能と扱わない。
