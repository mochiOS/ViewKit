# omochi — 共通部品の規則

omochiはmochiOSのネイティブUIに共通する造形・状態・動きの規則です。
ViewKitの既存のThemeと部品を実装基盤とし、並行する別のテーマは作りません。
Kinakoの確定仕様とユーザーのデザイン指定を優先します。

## 基礎

色、書体、余白、曲率、線幅は`resources/var`のFigmaエクスポートから生成する
`FigmaTokens`を基準にします。部品は`Theme`の意味別トークンを参照します。
アクセントは`Theme::with_accent`で一貫して反映します。ロゴ、標準アイコン、
Dockなどの個別の確定デザインを、共通部品の更新に便乗して変更しません。

| 用途 | 実装上の基準 |
|---|---|
| ボタン | `theme.button`、`theme.layout` |
| 入力欄 | `theme.text_field`、`theme.typography` |
| メニュー | `theme.menu`、`Menu::compact`、`Menu::group` |
| パネル | `Surface::floating`、`theme.surface` |
| カード | `Card`、`theme.card` |
| 余白・曲率・影 | `theme.spacing`、`theme.radius`、`theme.shadows` |
| 動き | `theme.motion` |

## 操作状態

- 通常、ホバー、押下、無効、キーボードフォーカスを区別します。
- ホバーは配置・寸法を動かさず、既存の状態色へ滑らかに遷移します。
- 押下の状態色、無効化、入力エラーは即時反映します。処理の実行を演出の終了まで待たせません。
- ポインターでフォーカスしてもキーボード入力先は維持し、外側のフォーカス枠は表示しません。
- Tabで移動した対象にはフォーカス枠を表示します。入力カーソルと選択表示は操作方法を問わず維持します。
- メニュー項目はButtonと同じ状態遷移を使います。メニュー全体の開閉は共通の表示用トークンを使います。

## 動き

ButtonとTextFieldは同じ色補間処理を使います。途中でホバーを反転した場合は、
その時点で表示されている色から次の状態へ移ります。初回描画は完成状態で表示し、
静止後はアニメーション用の再描画を止めます。

既存の`MotionTokens::DEFAULT`はfast=100ms、standard=180ms、slow=280msです。
これは現在の実装値であり、Kinakoの確定した最終値ではありません。
共通部品の状態色にはfastを使い、新たな数値を部品ごとに持たせません。
動きを抑える場合は`theme.motion = theme.motion.reduced()`を使います。

OSメニューの表示は、iPadの軽快な展開を参考に、左上の起点から92%→100%へ
一様に拡大する動きとフェードを組み合わせます。開くときは`menu`（220ms / ease-out）、
閉じるときは`menu_dismiss`（140ms / ease-in）を使います。過度な弾みは加えません。
これらと`menu_closed_scale`は調整用の提案値で、Kinakoの確定仕様ではありません。

`PaintContext::with_presentation`は配置を確定した子の描画命令だけを変換します。
文字サイズ・行高・クリップも同率で変換し、開閉中のレイアウト変更を避けます。
現在の透明度は要素単位で掛ける方式で、オフスクリーンのグループ合成ではありません。
アクセシビリティの座標はフォーカスを維持するため論理座標のままとし、ポインターは
描画に使った変換で逆変換します。キーボード・セマンティックコマンドの座標は変換しません。
閉じる処理は即時に実行し、残る描画は操作対象・フォーカス範囲から外します。
`VisibilityTransition`を所有側で保持し、途中反転時は直前の曲線で求めた位置から接続します。
終端で再描画を止め、`reduced()`では開閉を即時反映します。

現在の適用先はOSメニューと右上のコントロールセンターです。
コントロールセンターは右上を起点に同じ時間・倍率で展開し、スライダーの操作座標も
逆変換します。詳細画面は閉じる途中も保持し、グリッドへ切り替わることを防ぎます。
詳細を開く／戻るにはstandard（180ms）とspacing.extra_largeの短い横移動を使い、
グリッドと詳細を逆方向のフェードでつなぎます。配置は各画面の完成状態で固定し、
途中反転は同じ進行度から再開します。戻る途中も詳細を描画しますが、操作対象は
移動先だけに限定し、親のフォーカス範囲は切り替え中も維持します。パネル全体の
開閉と画面内の移動が重なる場合は、両方の変換を逆順に適用して入力座標を求めます。
コンテキストメニューへの同じ表示遷移の適用は、まだ行っていません。

Viewの再構築をまたいで操作状態を保持する場合は、アプリが所有する
`ButtonInteractionState`や`TextFieldInteractionState`を共有して渡します。
`Button::with_interaction_and_label`と`TextField::with_interaction`がその入口です。

## 確認用アプリと適用範囲

ViewKit Testに通常・アクセント・危険・無効ボタン、入力欄、エラー・無効入力欄、
メニューを並べています。色やフォントを変えず、ホバーの反転、押下、Tab移動を確認できます。
Buttonを使うメニュー、サイドバー、タブなども共通の状態描画を利用します。

通知センターのパネルには`Surface::floating`、通知には`Card`、グループの展開と
削除には`Button`を使います。開閉には`VisibilityTransition`とstandardの動きを使い、
閉じる途中で開き直しても表示位置を飛ばしません。グループ化とAppCoreからの
基本通知送信は接続済みです。返信・入力・進行状況などの通知内操作と、OS設定からの
動きの抑制は、未接続の機能として扱います。


## 操作面の粘弾性（参照モデルの移植・第1段階）

omochiの核は、操作した位置の周囲がへこみ、引くと輪郭の一部が伸び、力を離すと
保持時間に応じて形が戻る粘弾性です。単純な拡縮や減衰バネの追加とは区別します。

参照はリポジトリルートから`../omochi/playground/omochi.js`と
`../omochi/playground/button/index.html`です。`viewkit::omochi`へ次を移植しています。

- Burgersモデルのクリープコンプライアンスと正規化したクリープ量。
- 弾性・遅延弾性・粘性を保持時間に応じて混合した回復エンベロープ。
- 押した位置を基準にした局所的なへこみ、粘性を伴う追従、中心固定、先端の伸びと首の収縮。
- 部品ごとのMaterialと共通の物理計算。Buttonは参照のBUTTON素材を使います。

設定は`theme.motion.omochi`に集約しています。Nativeのイベント時刻を使い、短いクリックも
取りこぼさず、クリックの実行を回復アニメーションの終了まで待たせません。
キーボードは中央を押し位置として、キーを離すと回復します。文字・配置・クリック範囲と
アクセシビリティ座標は固定です。無効化・`reduced()`では変形を解除します。

描画には`DrawCommand::DrawContour`を使います。元の点列を0.68のtensionで平滑化し、
曲線の誤差に応じて頂点数を決めます。重複した閉点は平滑化前に取り除きます。
GPUは三角形と1物理pxのAA帯、CPUは同じ輪郭のパスを描画します。
角の押下で輪郭が折り返しても、非ゼロ巻き数規則で面を塗ります。
毎フレームSVGを再生成・画像化せず、画像アトラスを消費しません。
静止・回復完了後は再描画を止めます。

適用先はStandard・Primary・Accent・Dangerの独立したボタンです。
Ghost・Custom、Dock・システムバー・メニューなどに埋め込まれた操作は今回の対象外です。
`Button::omochi(false)`で比較用に無効化できます。
入力欄は参照のtext-fieldと同様に安定した面を保ちます。先に試した一様圧縮と
「ボタンの45%」という独自設定は取り除いています。

| 寸法 | 初期値と根拠 |
|---|---|
| 標準ボタンの高さ | 30px（参照の本体。SVG外側の余白を含めない） |
| 標準ボタンの曲率 | 9px（参照） |
| 標準ボタンの文字 | 13px（参照。フォントファミリーは既存テーマ） |
| 小／大の高さ | 24／32px（既存Spacingに基づく調整案） |
| 標準の左右余白 | 12px（デスクトップの密度のための調整案。従来18px） |
| 自動幅の下限 | 64px（既存Spacingに基づく調整案。明示幅を優先） |

標準寸法は`theme.controls`にまとめています。色・標準アイコン・Figmaエクスポートは
変更していません。参照値と今回の調整案は区別し、Kinakoの最終確定値とは扱いません。
ViewKit Testに3サイズと、動きあり／なしの比較欄を設けています。

Nodeで元のJavaScriptを評価した数値をテストへ保存し、クリープ・回復・局所変形の
一致を確認します。描画・入力・プロセス間転送についても別に検証します。

## 動く操作面（第2段階）

Switch・標準の横Slider・SegmentedControlへ、各playgroundの駆動と素材を適用しています。
Buttonの押し込みを全てに流用するのではなく、動く部位と力の入力を分けます。

| 部品 | 参照する入力と反応 |
|---|---|
| Switch | `switch/index.html`の指数追従、移動速度に応じた方向別の伸び（前72%・後28%）、首の収縮、押下の膨らみ |
| Slider | `slider/index.html`の速度入力（移動と逆向き・縦成分12%）、静止時の速度減衰、Burgers素材の回復、押下時の連続した最大20%拡大 |
| SegmentedControl | `segmented-control/index.html`の選択面の追従、進行方向の端を引く駆動、同じBurgers素材での変形・回復 |

素材は`Material::SLIDER`・`Material::SELECTION`へ集約しています。参照の形状を描画画像として
持ち込まず、既存テーマの部品寸法へ合わせた論理座標の輪郭を生成します。Switchの輪郭も
共通の曲線平滑化を使うため、参照のSVG点列との画素単位の一致は保証しません。
色・フォント・通常時の寸法・ラベル位置・ヒット領域は各部品の既存テーマを使います。

`SwitchInteractionState`、`SliderInteractionState`、`SegmentedControlInteractionState`を所有し、
`with_interaction(binding, state)`へ渡すことで、Viewの再構築や途中反転でも同じ操作面を保ちます。
Settingsは設定項目ごとにこれらを保持し、ViewKit Testにも実際に操作できる比較欄があります。
単に`new(binding)`を使う場合は、再構築時にBindingの遷移からSwitch・選択面の移動を再開できますが、
部品固有の変形履歴は新しくなるため、連続した操作には共有状態を推奨します。

Switchのドラッグ値はリリース時に確定し、描画中やアニメーション完了時に設定を書き換えません。
Sliderの既存の値域・刻み・ドラッグ終了時のcommit、選択部品の無効項目・キーボード操作は維持します。
変形は`DrawContour`で描き、静止時は通常の矩形描画へ戻ります。動きが収まれば再描画を停止し、
`theme.motion.reduced()`と無効化では変形を解除して確定位置を表示します。

今回の適用範囲に縦型のレベルSlider・Tabs・Stepper・スクロールバーは含みません。
入力欄は参照と同じく、文字入力を安定させる面として保ちます。
